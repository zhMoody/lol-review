## 2. 三条不变的布局纪律

1. **界面无彩色**。颜色由英雄头像提供。全局只有一处红（犯罪）。
2. **不用卡片**。结构靠通栏细线 + 留白 + 对齐（左右各 48px 硬边）。
3. **数字一律等宽**。对局中每秒刷新，等宽才不抖。

## 3. S3 · 对局中（`design/ingame.html`）

### 为什么是这个结构

**接口约束决定了形态。** `Live Client Data API` 的 `playerlist` 不给其他玩家当前血量，只给 `isDead` + `respawnTimer`。所以：

- ❌ 不能画血条（画了就是假数据）
- ✅ 重心压在「谁死了、还有几秒回来」——大乱斗最该问的就是**现在几打几**

### 分区

```
顶栏   12:43 · 海克斯大乱斗 · queue 2400        LIVE
头部   12:43（大字）  |  击杀 18:12 · 装备价值差 +2.4k · 塔 1:0
敌方   5 个头像（死亡的压暗去色 + 大号倒计时）
战场带 3 敌方阵亡 · 团战刚结束我方 3 换 1 · +2.4k
我方   5 个头像
日志   最近 3 条事件
```

### 数据来源与替代方案

| 想显示的 | 接口给不给 | 怎么做 |
|---|---|---|
| 生死状态 / 复活倒计时 | ✅ `isDead` / `respawnTimer` | 直接用，压暗 + 倒计时 |
| KDA / 等级 / 装备 | ✅ `scores` / `level` / `items` | 直接用 |
| **金币差** | ❌ 实时金币不给 | **用装备价值差替代**（`items.json` 售价求和）。大乱斗只能靠死亡购物，装备价值 ≈ 真实变现经济 |
| 当前血量 | ❌ | 不显示 |
| 实时符文选择 | ❌（`playerAugment*` 只在赛后记录里） | **显示已解锁槽位**：4 槽随 3/7/11/15 级解锁，空槽虚线 |
| 团战状态 | ⚠️ 无直接事件 | 由 3 秒内击杀数推断 |

### 符文槽位

`stats.playerAugment1..6`，实际只用 1–4。对局中虽然拿不到选了什么，但**知道解锁了几个**：已解锁未揭晓显示占位框，赛后补全真图标 + 中文名（图鉴见 07）。

## 4. S5 · 本局战报（`design/report.html`）

### 信息顺序 = 一次审判的顺序

```
结果（失败 · 28:41）
  ↓
对阵阵容图（敌方在上、我方在下，中间时间轴）—— 先看整体
  ↓
结论三栏（最 C / 在犯罪 / 在划水）—— 再给结论
  ↓
罪状清单 + 死亡位置图 —— 最后给证据
  ↓
详情条（点任意头像切换）—— 想深究就看这个
```

**为什么这样排**：从"发生了什么" → "谁的责任" → "凭什么这么说" → "展开细节"。这是打完一局人的自然心理路径。

### 对阵阵容图

- 两个队**都按评分降序排**。大乱斗没有分路，按分路排没有意义。
- 每行：序号 + 头像 88 + 名字 + KDA + 分数角标
- **红色描边 = 犯罪**，**底部白线 = 当前查看**（两套状态不抢同一个位置）
- 头像是主角，界面退后

### 罪状清单（核心差异化）

每次白给阵亡一条，格式固定：**时间 + 地点 + 可查证的理由**

```
14:22  中路      团战开打前 8 秒阵亡 → 45 秒后丢二塔
22:15  敌方塔下  吸收伤害仅为全队均值的 31%，秒躺
24:40  中路      死时携带 2,340 金币未花，浪费唯一购物窗口
26:02  我方高地  我方 4 人存活时无意义阵亡，直接掉高地
```

**硬规则：裸标签不给。**「蛆」后面必须跟理由，理由里的数字必须来自时间线（`CHAMPION_KILL` 事件带 `victimId / timestamp / position`）。这是产品可信度的来源，也是市面工具都没做的事。

### 死亡位置图

嚎哭深渊是单线，把时间线里的 `position{x,y}` 投影到线轴上：

```
我方  ○─●─●─○─●─●─○  敌方
      高地    中路     塔下
```

实心红 = 白给阵亡，空心 = 正常阵亡。一眼看出"这个人死得有多冒进"。

### 详情条

点任意头像切换。六项指标 + 细条 + 强化符文（真图标 + 中文名）。

## 5. S1 · 已连接 · 空闲（`design/home.html`）

**这一屏是战报的入口，也是产品用得最多的一屏。**

```
身份块   头像 88 + 名字 + 等级 / 段位 / 场次     近 20 局胜率 · 场均 KDA · 平均评分
最近战报 6 行，每行 = 胜负点 + 英雄头像 + 名字时间 + KDA + 时长 + 评分 + 人设标签
汇总条   近 6 局胜负 · 当过蛆王 N 次 · 平均阵亡      [等你开一局]
```

设计要点：
- **每行都可点进去看完整报告**，这是产品闭环：S1 是历史，S5 是单局。
- 蛆那一行左边有 2px 红色 hover 条（`.row.crime`），不用整行染色。
- 「当过蛆王 N 次」用 `--danger`——这是整蛊，但它也是最有粘性的一个数字。
- 「等你开一局」是虚线框 + 呼吸点，**不用大色块**。

## 6. S2 · 选人阶段 / 队友情报（`design/teammates.html`）

大乱斗是**随机英雄**，所以"选人"实际是「英雄牌 / 重随」：

- 每人一张随机英雄，可以花重随次数换
- **看不到敌方英雄**（进游戏才揭晓）
- 所以这一屏的重点是**人**

```
头部   队友情报           重随 2/2
括号   └─ 开黑 · 2 人 ─┘   ← 跨卡括号，纯线条，不用彩色
卡片×5 头像 + 名字 + 段位熟练度 / 胜率 + KDA + 走势 sparkline / 场次常用 / 标签
预言   开场预言 + 打完自动对答案
```

### 开黑关系怎么表达

**不用彩色标签，用跨卡括号。** 一根线把两个卡框起来，标「开黑 · 2 人」。
理由：开黑是**关系**不是**属性**，画在人头上不如画在人与人之间。而且保持了"界面无彩色"的纪律。

### 每张卡的四段

| 段 | 内容 | 数据来源 |
|---|---|---|
| 头 | 英雄头像 + 召唤师名 + 段位 + 熟练度 | `/lol-summoner/v1/summoners/{id}` + champion mastery |
| 战 | 近 20 局胜率（大字）+ 场均 KDA | `/lol-match-history/v1/products/lol/{puuid}/matches` |
| 势 | 10 格 sparkline（实心=胜，空心=负） | 同上 |
| 底 | 大乱斗场次 + 常用英雄 + 一个标签 | 同上 |

标签是**数据驱动**的，不重复：
- 胜率最高 →「近 20 局最稳」
- 场次最多 →「老乱斗」
- 场均阵亡 > 9 →「场均阵亡 9.7」（`--danger`）
- 助攻/击杀比高 →「助攻型」
- 其余 →「正常发挥」

### 开场预言（整蛊，但可查证）

> 「路人甲」近 20 局场均阵亡 9.7，本局他大概率会死 9 次以上。
> 打完自动对答案。

数据来源就是近 20 局战绩。**预言错了更好笑**，所以不用怕不准。

## 8. 交互状态（全屏通用）

| 元素 | 状态 | 表现 |
|---|---|---|
| 英雄头像 | 常态 | 1px 描边 `#2A2A2E` |
| | 犯罪 | **1.5px 描边 `--danger`** |
| | 当前查看 | **底部 2px 白线** |
| | 阵亡 | 灰度 + 亮度 .35 + 大号倒计时 |
| | hover | `translateY(-3px)` + 描边变亮，180ms |
| 数据条 | 变化 | 宽度 600ms `--e` |
| 区块 | 进入 | opacity + `translateY(8px)`，280ms，stagger 40ms |
| 状态灯 | LIVE | 呼吸 1.6s（对局中）/ 2.4s（空闲） |

动效总共只有 4 个。上一版有 12 个，删掉了所有光晕、回弹、count-up、卡片浮起。
