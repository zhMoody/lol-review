# 06 · 窗口形态与设置页

> 决策来源：2026-10-26 讨论。用户要求 **三种形态都做，由设置页自选**。
> 这条决策意味着界面不是"一套尺寸"，而是"一套状态机 + 三套投影"。本文档定义投影规则。

---

## 1. 核心架构：一套状态机，三种投影

```
            ┌──────────────────────────┐
            │  State Machine (S0…S5)   │  ← 唯一真相，与形态无关
            │  纯数据：players/events  │
            └────────────┬─────────────┘
                         │ 同一份 state
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
   View: Main       View: Bar        View: Overlay
   1180×760         420×168          自适应 320~560
   （全状态）        （S1/S3）         （仅 S3）
```

**铁律**：切换形态**不重置状态机**、不重连接口、不丢数据。形态只是"同一份数据换个画布"，实现上是一个 `useViewMode()` 加三套渲染树，共享同一个 store。

判断标准（写代码时自查）：如果切换形态后需要重新请求接口，说明投影写错了。

---

## 2. 三种形态定义

### W1 · 主窗（Main）

| 项 | 值 |
|---|---|
| 默认尺寸 | 1180 × 760 |
| 最小尺寸 | 960 × 640 |
| 最大 | 无限制（内容 `max-width: 1360` 居中） |
| 置顶 | 默认否，可在设置里开 |
| 任务栏 | 有图标 |
| 支持状态 | **全部 S0–S5** |
| 系统托盘 | 关闭窗口时最小化到托盘（可设"直接退出"） |

主窗是"完整功能画布"。所有形态里只有它能看报告全文、看历史、进设置。

### W2 · 悬浮条（Bar）

| 项 | 值 |
|---|---|
| 尺寸 | 420 × 168（固定，不可缩放） |
| 位置 | 记忆上次位置；默认屏幕右侧居中 |
| 置顶 | **强制 alwaysOnTop** |
| 边框 | 无边框（`frame: false`），自绘 1px 描边 + 8px 圆角 |
| 拖动 | 整条可拖（`-webkit-app-region: drag`，交互元素 `no-drag`） |
| 支持状态 | **仅 S1 / S3**（S3 时最有用） |
| 其他状态 | S0 显示灰点「未连接」；S2 显示「选人中 24s」；S4/S5 显示「报告已就绪 →」可点开主窗 |

悬浮条的内容（最小可用信息集）：

```
┌────────────────────────────────────┐ 420×168
│ ● 对局中  26:14      +1.2k   ⤢     │ 24px 顶条
├────────────────────────────────────┤
│ CARRY ███████░░  TEAM █████░  ⚑    │
│ Ahri      12/4/7     ████ ███ ▯ 73 │ 28px
│ Lee Sin    5/9/13    ███  ████ ██ 59│ 28px
│ Yasuo      2/11/4    █    █   ████ 28│ 28px
│ Jinx       6/7/5     ███  █   ███ 52│ 28px
│ Lulu       1/6/16    █    ███ ██  41│ 28px
└────────────────────────────────────┘
```

- 只显示**我方 5 人**。敌方在悬浮条上永远不显示（信息密度不够，且对局中看敌方数据容易分心）。
- 每行只有：名字 / KDA / 三条极短轨道（各 36px 宽，2px 高）/ 总分。
- **人设色只出现在总分数字上**，不做标签（空间不够）。
- 双击任意行 → 打开主窗并定位到该玩家。
- 右上 `⤢` → 展开为主窗（保持当前状态）。

### W3 · 游戏内叠加（Overlay）

| 项 | 值 |
|---|---|
| 尺寸 | 自适应 320–560 宽，高度按内容 |
| 背景 | `rgba(8,13,21,.82)` + 8px 圆角（**不做全透明**，否则游戏亮场景下文字读不清） |
| 置顶 | 强制 `alwaysOnTop` + `setIgnoreMouseEvents(true)`（默认穿透点击，hover 时才接收） |
| 位置 | 4 个吸附锚点：左上 / 右上 / 左下 / 右下 + 自由拖动 |
| 透明度 | 设置项 50%–100%，默认 85% |
| 支持状态 | **仅 S3**（进入 S3 自动淡入，离开自动淡出） |
| 内容 | 5 行我方迷你评分，无顶条、无装饰 |

**Overlay 的合规与风险（必须写进设置页的提示文案）**：
- 只显示官方接口已公开的数据，不显示技能 CD、不显示敌方视野。
- 仅"读"，不做任何自动化。
- 全屏独占模式（Fullscreen Exclusive）下可能被游戏遮挡（操作系统层面无法穿透），此时需切到"无边框窗口"模式。设置页要明说这一句。

---

## 3. 形态之间的切换

| 规则 | 说明 |
|---|---|
| 主形态 | 用户在设置里选 `主形态 ∈ {W1, W2}`，决定"点开 App 时先出现哪个" |
| 叠加层 | `启用游戏内叠加` 是独立开关，可与任何主形态同时开（对局中才出现） |
| 快捷键 | 全局快捷键（默认 `Ctrl/Cmd + Shift + L`）：显示/隐藏当前主形态窗口 |
| 对局自动弹出 | 可选「进入对局时自动显示悬浮条」（默认开） |
| 对局结束 | 悬浮条/叠加层自动收起，主形态切到 S4→S5 |
| 状态保持 | 切换形态只换渲染树，store 不变（见 §1 铁律） |

## 4. 设置页规格

入口：顶栏齿轮。以**主窗内的一级页面**呈现（不是模态），左栏分类 + 右栏内容，走与报告页同一套状态切换动画。

```
┌──────────────┬──────────────────────────────────────────┐
│ 常规          │  窗口形态                                 │
│ 窗口形态  ◀   │                                          │
│ 数据与接口     │  主窗口          ( ) 独立窗口             │
│ 评分          │                  (•) 悬浮小条            │
│ 外观          │                                          │
│ 关于          │  游戏内叠加      [ 开 ]                   │
│              │  位置            [右下 ▾]                 │
│              │  不透明度        ────●────  85%           │
│              │                                          │
│              │  ⓘ 全屏独占模式下叠加层可能被游戏遮挡，     │
│              │     请使用无边框窗口模式。                 │
└──────────────┴──────────────────────────────────────────┘
```

### 4.1 六个分区与字段

**① 常规**
- 开机自启（默认关）
- 启动时最小化到托盘（默认开）
- 关闭窗口时：最小化到托盘 / 直接退出（默认前者）
- 全局快捷键：显示/隐藏窗口（默认 `Ctrl/Cmd+Shift+L`）
- 语言：简体中文（P1 仅此一项，不做多语言 UI，但文案走 key 表）

**② 窗口形态**（本文档 §2、§3）
- 主窗口形态：独立窗口 / 悬浮小条
- 启用游戏内叠加（默认关，因为需要用户理解风险）
- 叠加层位置：左上 / 右上 / 左下 / 右下 / 自由
- 叠加层不透明度：50–100%，默认 85
- 进入对局时自动显示（默认开）

**③ 数据与接口**
- 客户端安装路径（自动探测 + 手动指定 + "重新探测"）
- 轮询频率：实时（2s）/ 省电（5s）（默认实时）
- 本地数据保留：最近 20 局 / 50 局 / 全部（默认 20）
- 「导出诊断信息」：把最近一次连接日志打包（用于排查"接不上"）

**④ 评分**
- 报告默认排序：按风险（默认）/ 按总分
- 人设用词：直白（默认，见 §5）
- 显示敌方评分：（开）—— 关掉后报告只显示我方 5 人
- 重开局不生成报告：（开，不可关）

**⑤ 外观**
- 强调色：金（默认，唯一选项，P1 不做换肤）
- 数字字体：等宽（默认，不可关，关掉会抖动）
- 动效：完整 / 精简 / 关闭（默认完整，等价于 `prefers-reduced-motion` 的强制开关）

**⑥ 关于**
- 版本、更新检查
- **合规声明**（必读，展开式）：只读官方本地接口、不做自动化、不展示隐藏信息
- 免责：非 Riot 官方产品，不承担账号风险
- 开源许可

## 5. 人设用词（已定：直白）

| key | 中文（直白，默认） | 颜色 |
|---|---|---|
| `persona.carry` | 大腿 | `--p-carry` |
| `persona.try` | 尽力局长 | `--p-try` |
| `persona.solid` | 中规中矩 | `--p-solid` |
| `persona.tool` | 工具人 | `--p-try` |
| `persona.passive` | 混子 | `--p-passive` |
| `persona.invisible` | 隐形人 | `--p-passive` |
| `persona.lonewolf` | 独狼（副标签） | `--p-solid` |
| `persona.crime` | 蛆（主）/ 犯罪嫌疑人（副标题） | `--p-crime` |
| `persona.pending` | 待定（数据不足） | `--text-low` |

实现约定：**代码里只出现 key，不出现中文**。文案集中在 `i18n/zh-CN.ts`，这样以后要加"文明模式"只是多一份表，不动逻辑。

「蛆」的使用规则：只在**主标签**上出现，且必须紧跟一句可验证的理由（"11 次阵亡，3 次死在小龙刷新前 45 秒"）。**裸标签不给**——这是避免变成纯粹的人身攻击，也是产品的可信度来源。

## 6. 各形态的 token 差异

同一套 token，三种形态只在**字阶与密度**上分档：

| 项 | W1 主窗 | W2 悬浮条 | W3 叠加 |
|---|---|---|---|
| 正文字号 | 13 | 12 | 12 |
| 行高 | 42–56 | 28 | 26 |
| 三轨高度 | 4px | 2px | 2px |
| 卡片圆角 | 10 | 8 | 8 |
| 人设标签 | 有 | 无（仅数字着色） | 无 |
| 金色元素上限 | 3 | 1 | 1 |
| 阴影 | `--elev-1` | `--elev-3` | 无（用背景不透明度代替） |

叠加层额外要求：**文字必须 ≥ 12px**，且所有文字加 `text-shadow: 0 1px 2px rgba(0,0,0,.8)`（游戏画面亮色背景下唯一能保证可读的手段）。

## 7. 实现拆分（P1 阶段就要定死，避免返工）

```
renderer/
├─ views/
│  ├─ main/            S0…S5 全量页面
│  ├─ bar/             BarShell + 5 行紧凑列表
│  └─ overlay/         OverlayShell + 5 行极简列表
├─ components/         三形态共享的原子组件（C-01…C-12 中标记 ●shared 的）
└─ hooks/useViewMode.ts 返回 'main' | 'bar' | 'overlay'
```

`components/` 里哪些必须共享：`ScoreBar`、`PersonaTag`、`StatDelta`、`StatusDot`、`ChampionAvatar`。
哪些各写各的：`PlayerRow`（三种密度差异太大，强行抽会导致 props 爆炸，**分开写**）。

> 这是一条反"过度抽象"的决定：三套 PlayerRow 各 60 行，比一个塞满 density 分支的 300 行组件好维护。

## 8. 验收

| # | 场景 | 期望 |
|---|---|---|
| V-01 | 主窗 → 悬浮条 切换 | 状态不丢，当前局数据仍在 |
| V-02 | 悬浮条置顶覆盖在浏览器上 | 正常显示，可拖，不抢焦点 |
| V-03 | 进入对局 | 悬浮条/叠加层 320ms 内自动出现 |
| V-04 | 退出对局 | 叠加层淡出，主形态切到报告 |
| V-05 | 叠加层点击穿透 | 游戏内点击不被拦截（除 hover 时） |
| V-06 | 关闭叠加层开关 | 立即消失，下次启动仍为关 |
| V-07 | 三形态同时开 | 数据一致，不重复请求接口 |
