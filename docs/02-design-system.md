# 02 · 设计系统（中性极简）

> 唯一现行方案：**A · 中性极简**。参考实现：`design/report.html`、`design/ingame.html`
> **没有版本号。这是最终版。**

---

## 0. 为什么推翻

上一版的根本问题不是"颜色不好看"，是**颜色太多、分工不清**：

- 深蓝底 + 金色强调 + 青色团队 + 红色风险 + 橙色对局中 = 5 个色相同时存在
- 用户要先分辨"这个青是什么意思"，才能开始看数据 → 认知成本前置
- 英雄头像本来就是彩色的，界面再上 5 个色相，等于两套色谱打架

**新原则：界面无彩色，颜色由英雄头像提供。**

界面只保留三档灰 + 一处红。这样有 10 个彩色英雄头像是"画面"，界面是"画框"。既极简，又不寡淡。

## 1. 色彩 Token

### 1.1 极黑与灰阶

| Token | Hex | 用途 | 对比度 vs `--bg` |
|---|---|---|---|
| `--bg-deep` | `#060607` | 窗口最外层（比内容区更黑） | — |
| `--bg` | `#0A0A0B` | 主内容区 | — |
| `--surface` | `#131315` | 极少数需要"抬起"的区块 | — |
| `--surface-2` | `#1A1A1D` | 图片占位 / 输入框 | — |
| `--line` | `#232326` | 需要看见的分隔线 | — |
| `--line-soft` | `#1A1A1D` | 区块之间的细线（默认） | — |
| `--text-hi` | `#F2F2F3` | 标题、关键数字、名字 | **19.2:1** ✅ |
| `--text-mid` | `#9E9EA4` | 正文 | **8.4:1** ✅ |
| `--text-low` | `#6A6A70` | 标签、辅助（≥12px 可用） | **4.2:1** ✅ |
| `--text-ghost` | `#3E3E43` | 纯装饰（序号、版权行） | 1.9:1 ⚠️ 仅装饰 |

> **没有第二套灰阶。** 所有层级差异靠这 4 档文字色 + 2 档线色表达。任何新组件都不许引入第 5 档。

### 1.2 唯一的彩色

| Token | Hex | 用途 | 使用规则 |
|---|---|---|---|
| `--danger` | `#D9534F` | **"犯罪"语义** | 全屏同时出现 ≤ 2 处：一处头像描边 + 一处阵亡数字 |

三条硬规则：
1. **红色只表示"有害"**。不表示失败、不表示敌方、不表示错误提示。
2. **胜负不用颜色**。胜利用 `--text-hi` 满色，失败用 `#C8C8CC`（略降 8%），只差这一档。用户读的是字，不是色块。
3. **全屏红色元素数量 ≤ 2**。超过 2 处说明这一局有多人在犯罪，那就不该用"一个人"的视觉语言，改用列表排序。

### 1.3 数据可视化

**只用明度，不用色相**：

| 层级 | 值 | 用途 |
|---|---|---|
| 主数据条 | `#F2F2F3` | 输出、主要贡献 |
| 次数据条 | `#8A8A90` | 团队、次要贡献 |
| 底槽 | `#26262A` | 轨道背景（必须可见！） |
| 风险条 | `#D9534F` | 仅风险轴 |

> 底槽 `#26262A` 是硬性要求：上一版用 `#172335` 放在 `#0C141F` 上几乎不可见，条形码判读直接失效。任何情况下底槽与卡面亮度差 ≥ 12%。

### 1.4 强化符文品质色（唯一豁免）

强化符文是**游戏内既定的品质体系**，改色会造成误读，因此允许三个固定色相，但只用于符文图标，且单个 ≤ 28px：

| Token | Hex | 品质 |
|---|---|---|
| `--aug-silver` | `#B9C0C8` | 白银 |
| `--aug-gold` | `#D9AE5F` | 黄金 |
| `--aug-prism` | `#B08CFF` | 棱彩 |

除此之外，界面里不允许出现任何其他色相。**这是唯一的例外，不要为别的功能再破例。**

## 2. 字体

| Token | 值 | 用途 |
|---|---|---|
| `--sans` | `-apple-system, "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", sans-serif` | 全部中文与文案 |
| `--mono` | `ui-monospace, "SF Mono", "JetBrains Mono", Menlo, monospace` | **所有数字**：KDA、伤害、金币、时间、分数 |

| Token | 值 | 字重 | 用途 |
|---|---|---|---|
| `--fs-nano` | 9.5px | 400 | 序号、轴标签 |
| `--fs-micro` | 10px | 400 | 单位、角标、小标签 |
| `--fs-cap` | 11.5px | 400 | 辅助说明 |
| `--fs-body` | 12.5px | 400 | **默认正文** |
| `--fs-name` | 14px | 500 | 英雄名、区块标题 |
| `--fs-num` | 17–26px | 400 | 数据数字（等宽） |
| `--fs-verdict` | 21px | 500 | 结论人名 |
| `--fs-result` | 58px | 700 | 结果大字（全屏仅 1 处） |

字母间距：中文 0，英文与数字 +0.2~0.4px，结果大字 +10px（拉开的字距是"海报感"的来源），小标签 +1~2px（全大写或散排标签必须加）。

## 3. 间距与结构

4px 基准：`4 / 6 / 8 / 12 / 14 / 18 / 26 / 40 / 48`

**核心原则：不用卡片。** 上一版每个区块都套 1px 边框 + 圆角 + 阴影，结果是"盒子套盒子"，密不透风。新版结构靠三件事建立：

1. **全幅通栏的分隔线**（`--line-soft`，左右贯穿到窗口边缘，不是"卡片边框"）
2. **留白**（区块间距 26–40px，比上一版大 1.6 倍）
3. **对齐**（所有内容左右各 48px 内边距，形成一条硬边）

| 圆角 | 值 | 用途 |
|---|---|---|
| `--r-xs` | 4px | 角标、品质块 |
| `--r-sm` | 5–6px | 按钮、标签 |
| `--r-md` | 8–10px | 英雄头像、输入框 |
| `--r-lg` | 12px | 窗口 |

> 头像圆角用 **10px**，不用正圆。正圆会把英雄的构图切掉，方形能保留更多画面，也对齐感更强。

## 4. 动效

极简方案下，动效只剩三个用途：**进入、状态变化、数值变化**。

| Token | 值 | 用途 |
|---|---|---|
| `--d-instant` | 90ms | hover 反馈 |
| `--d-fast` | 180ms | 位移、描边变化 |
| `--d-base` | 280ms | 区块进入 |
| `--d-data` | 600ms | 数据条描画 |

| 曲线 | 值 |
|---|---|
| `--e` | `cubic-bezier(.22,1,.36,1)`（唯一曲线） |
| `--e-line` | `linear`（仅呼吸灯） |

**删掉的动效**（上一版有，新版一律不要）：
- ❌ 金色扫光、发光、光晕
- ❌ 标签回弹（`--e-pop`）
- ❌ 骨架屏闪烁
- ❌ 卡片浮起（`translateY` 悬停）
- ❌ 数字 count-up（数据页要瞬间可读，滚动动画只增加等待）

**保留的动效**：
- ✅ 头像 hover：`translateY(-3px)` + 描边变亮，180ms
- ✅ 区块进入：opacity + `translateY(8px)`，280ms，stagger 40ms
- ✅ 数据条宽度变化：600ms（仅切换查看对象时）
- ✅ 状态灯呼吸：2.4s，`linear`，opacity .25↔1

`prefers-reduced-motion: reduce` → 全部关闭，直接显示终态。

## 6. 布局规则（报告页）

```
内边距 48（左右硬边）
通栏分隔线：左右贯穿到 0，不是 48 起
区块顺序：结果 → 敌方阵容 → 时间轴 → 我方阵容 → 结论三栏 → 详情 → 页脚
```

三条不可违反：
1. **阵容区是画面的主体**，必须占据首屏 45% 以上高度。
2. **两条阵容之间必须有时间轴**，这是"对阵"的视觉支点，不能省。
3. **结论三栏不做卡片**，只用竖线分隔，且三栏等宽（不平衡会让人以为有权重）。
