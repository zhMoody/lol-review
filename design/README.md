# design/ · 设计稿目录

> **这里的 .html 是「可交互的设计稿」，不是产品代码。**
> 程序方案尚未确定，所以本目录不承担任何工程质量责任。
> **没有版本号。做到的就是最终版，旧的已删除。**

---

## 设计稿是什么

用浏览器能打开的单文件 HTML，目的是：
- 把**布局、间距、字重、颜色、层级**说到能照着实现的程度
- 把**交互流程**演出来（点击切换、悬停状态、状态变化）
- 用来做**设计评审**，而不是用来交付

## 设计稿不是什么

| 不是 | 说明 |
|---|---|
| ❌ 不是组件库 | 样式全部内联写死，没有抽 token，没有复用 |
| ❌ 不是可维护代码 | 没有类型、没有测试、没有错误处理 |
| ❌ 不是性能基线 | 图片走 CDN，动画不做优化，只为好看 |
| ❌ 不是真实数据 | 所有数字都是编的，且**必须编得像**（见下） |
| ❌ 不是最终视觉 | 每一版都可能被推翻，`archive/` 里的就是被推翻的 |

## 唯一的原则：数据要编得像

设计稿里的假数据不能随便填，否则评不出问题。规则：
- 数字之间要**自洽**：伤害占比之和 ≈ 100%，承伤与阵亡次数不能矛盾
- 要包含**极端样本**：一定要有一个 0/12/3 的，也要有一个 2/8/21 的
- 要包含**边界情况**：数据缺失、重开局、全员平庸无人可骂

## 转成工程时必须重做的事

等程序方案定了，这些**全部要重做**，不能搬运：

| 项 | 设计稿现状 | 工程要求 |
|---|---|---|
| 颜色 | 每个文件重复声明一遍 `:root` | 抽成唯一 token 文件 |
| 布局 | 绝对像素写死 | 响应式 + 最小窗口适配 |
| 组件 | 每个页面重新写一遍 | 抽成组件，props 化 |
| 数据 | 硬编码在 HTML / 一个 JS 数组里 | 走 IPC，接状态机 |
| 图片 | CDN 直连 | 本地缓存 + 失败降级 |
| 动画 | CSS animation | 统一 motion 层 + reduced-motion 全局开关 |
| 无障碍 | 只做了一部分 | 完整键盘导航 + 语义标签 + 对比度校验 |

> 换句话说：设计稿的价值在"长什么样、怎么动、点哪里会发生什么"，不在"怎么写"。
